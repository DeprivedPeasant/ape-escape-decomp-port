# Native Windows area renderer (generated)

Generated by `uv run --offline python tools/codex/check_native_viewer.py`.

## Milestone and scope

A standalone native Windows C11 executable loads locally prepared area assets, uploads RGBA textures to OpenGL and renders terrain and placed props in an SDL3 window. No emulator, BIOS, original game executable or Python interpreter is needed at runtime. Preparation reads the extracted game data through the existing Python OBJ/VRAM tools. Animated Spike and original static floor/wall responses are integrated in the separate walking harness (notes/66-69). Enemies, gimmicks and the original player/game loop remain incomplete.

## Run

From the repository root, using installed GCC and existing extracted data:

```powershell
uv run --offline python tools/codex/setup_sdl.py --download
uv run --offline python tools/codex/build_native_viewer.py --area 0x01 --run
uv run --offline python tools/codex/build_native_viewer.py --area 0x01 --capture
uv run --offline python tools/codex/pack_area.py --all
uv run --offline python tools/codex/check_native_viewer.py
```

Executable, area packs and captures live in `extract/codex/native/` (gitignored). The executable can be launched directly with a pack path. SDL3.dll is copied beside it; the OpenGL driver remains a system dependency. Assets are not embedded into it.

Controls: WASD move the camera target, Q/E lower/raise it, Shift moves faster; hold right mouse button to orbit, mouse wheel zooms, arrows rotate. C toggles collider wireframes, T toggles textures, Home resets the camera, Escape exits. The initial view fits visible terrain, falling back to prop bounds in terrainless areas.

Animated Spike and terrain walking are available through the build runner's `--spike` / `--player` options (notes/66-68). The checks here isolate the area renderer.

## Asset adapter and format

`pack_area.py` imports `export_area_obj.py`, `dump_areas.py` and the existing PNG structural checker. It never edits them. It reads OBJ/MTL/PNG output, expands triangle vertices into xyz/uv/rgb records, flips texture rows to match OBJ UV origin, doubles textured RGB modulation (PSX 128 is neutral), and excludes cells whose original bit0 is clear or areas whose header disables terrain. Collider triangles form a separate optional draw class.

AEV1 is a new local prepared format, not a recovered game format. All words are little endian: 64-byte header (`8s8I6f`: magic AEVIEW1 + NUL, version, area, member, vertex/batch/texture counts, terrain/prop triangle totals, visible min/max xyz); 16-byte batches (`first,count,texture,kind`); 32-byte vertices (`xyz,uv,rgb` floats); each texture has `width,height,byteCount` u32 followed by bottom-origin RGBA8. Texture 0xFFFFFFFF means untextured. Kinds 0/1/2 are terrain/prop/collider. This explicit adapter leaves future direct game-data loading independent of rendering.

## Limits and next integration

The renderer uses OpenGL 1.1 client arrays with nearest textures, alpha testing and depth testing. It does not reproduce the PSX ordering table, fixed-point/GTE lighting, fog, semi-transparent blend modes, animated VRAM, zone culling, terrain subdivision or far-block LOD. Terrain geometry inherits the exporter's center fan approximation and prop rotation assumptions. Collider boxes are visualization aids; no collision behavior is implied.

SDL3 handles windows, OpenGL contexts, events, keyboard/mouse input, gamepad hotplug, dual-stick development controls and timing. Optional `--music-bank extract/members/059.bin` with `--collision-exe extract/disc/SCUS_944.23` streams Claude’s portable music engine through SDL3 (44.1 kHz stereo float). It does not yet route game sound events. Left stick moves, right stick orbits, Start pauses animation; original gadget controls remain work ahead.

The pinned official SDL3 MinGW SDK is 3.4.18; setup_sdl.py verifies its published SHA-256 and keeps it under ignored extract/codex/deps/. Once present, builds and checks run offline. A CMake build is available in the top-level CMakeLists.txt; point SDL3_DIR at the SDK’s lib/cmake/SDL3 directory. Only Windows has been validated.
