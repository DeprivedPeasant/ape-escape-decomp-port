# Native particle bytecode VM (generated)

Generated by tools/codex/check_native_effects.py, using the installed GCC compiler and Python ctypes. The C11 sources are original implementations of the documented behavior, not copied decompiled code. No dependencies are installed; DLL/results remain ignored under extract/codex.

Run: `uv run --offline python tools/codex/check_native_effects.py`. Standalone build: `gcc -std=c11 -O2 -Wall -Wextra -Werror -shared src/effects/effect_vm.c -o extract/codex/effect_vm.dll`. The caller can also compile the C source directly into its native executable and include effect_vm.h.

src/effects/effect_vm.c and effect_vm.h expose initialization and one update on a single isolated particle. The state retains the exact 52-byte little-endian image and PSX 32-bit script/loop addresses; host pointers stay outside it. Reads are bounded, host alignment is irrelevant, and signed shifts use defined arithmetic instead of implementation-dependent C shifts. Writes explicitly wrap.

This runs natively on Windows and has no renderer, allocator, GTE, audio or game-loop dependency. Its caller supplies a borrowed script buffer, PSX address origin, RNG seed and ground/water thresholds. It counts ground/water/ribbon events and offers an optional callback with opcode operand and a borrowed state snapshot at the event point. The hook must not mutate/re-enter the context. It does not reproduce the external draw/spawn bodies. The header describes lifetime, status/error codes and the frame snapshot API.

Differential validation: 4512 real runs over 94 extracted scripts, 16 seeds and three collision profiles; 70883 frame snapshots. Every frame compares all 52 bytes, RNG seed/call count, PC, frame/command counts, termination reason and callback counts against the Python reference. Callback operands and all event-point state bytes are also compared. Dead-slot updates are checked for stability.

Additional synthetic validation: 1138 runs / 7960 frames. All 46 legal opcodes execute, including the 10 absent from real pools. Deterministic random instruction sequences exercise full signed halfwords, RGB/UV byte wrapping, size scaling, loops, waits and overflow of PSX address origin. The overflow fixture exposed a missing uint32 mask in the Python loop jump, now corrected; real script results were unaffected. 9 diagnostic cases cover illegal/truncated streams, bad loop depth, missing terminator, non-yielding command budget and invalid initial ranges. Compiler warnings are errors.

Limits: differential agreement establishes consistency with the checked reference, not independent instruction-for-instruction PSX equivalence. The C VM starts from the same isolated reset state; shared pool RNG order, partially reused slots, draw-before-update ordering and external callbacks need integration at the native-port game-loop boundary. Negative error returns are diagnostic stops, not a claim about the original game handling corrupted data.

Failures: 0. Context size on this Windows build: 136 bytes (host ABI metadata; the game state image itself remains 52 bytes).
