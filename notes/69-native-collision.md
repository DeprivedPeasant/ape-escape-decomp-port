# Native collision reconstruction

Generated by `tools/codex/write_collision_notes.py`; reports remain under ignored `extract/codex/native/`.

## Solid shape handlers

`native_collision.c/.h` reconstruct the ten handlers dispatched by the 89-entry table at 0x800AF180. Coordinates remain integer PSX units with negative Y upward. Native code embeds neither original instructions nor original lookup-table bytes.

All 55,494 real shape records and 3,844 collider records were inventoried across 101 areas. Shape validation: 237,882 original-instruction comparisons, failures=0. Nonzero output seeds verify preserved slopes and output values on misses as well as hits.

The test-only MIPS interpreter executes the original extracted EXE instructions, including branch/load delay slots, integer division, GTE SQR and the leading-zero counter. It is not used by the native runtime.

Both original square-root routines pass 10,242 comparisons. SDK SquareRoot0 uses a normalized lookup and truncation; all 192 lookup entries equal floor(sqrt(index * 262144)), allowing their values to be calculated without embedding game data. IntSqrt uses an extra digit and rounds; its final wrapped variable shift is retained for large inputs.

Real shape types include 64 and 66 (underside/overhang variants), contrary to the earlier assumption that those variants were unused. Types 74–77 leave a caller register unspecified outside their center square and occur only as strip collider types, not as grid shapes; these undefined direct-call cases are excluded from synthetic shape tests.

## Shape grid and contact selection

`ae_collision_load` bounds-checks original member headers, tables, grid indices and shape links, rejects unknown handler types and cycles. `ae_collision_grid_height` follows each column, including the tall-surface continuation into the next height band, and returns the original contact kind/index/type/extra fields and slopes.

Traversal validation: 166,622 original GetSolidHeight queries across 101 areas, including 43,222 selected contacts; failures=0. Collider count is set to zero only in this oracle run to isolate shape-grid behavior.

## Complete floor selection and movement

Separate collider floors are now native: boxes, linear/overhang/wedge ramps, diagonal boxes, radial pillars, half-pipes, rings, strips, trenches and curved slopes. Water-top selection is included. `ae_collision_ground_height` combines terrain and solids, preserving original contact metadata even when the terrain floor is higher. Negative-band shapes may write contact/surface flags while returning the 32767 sentinel.

Collider scans restart immediately when a newly selected floor raises the probe. A half-pipe clears only one slope component; the other retains its prior value. Differential tests exposed both details, and original instruction traces established the exact behavior.

SDK vector normalization values are calculated arithmetically. The original angle lookup is loaded as an external asset from `extract/disc/SCUS_944.23`, never embedded in source. Supply `--collision-exe` when launching outside the repository root.

## Collision response investigation

Private Ghidra exports: `notes/decomp/codex/collision-shapes.c`, `collision-helpers.c`, `collision-math.c`, `collision-resolve.c`, `collision-probes.c`, `collision-curved-response.c` (ignored, not committed).

`BodyCollideColliders` (0x800792C8) records the containing collider at body+0x34; it does not push the body. Horizontal push and ceiling response are in `CollisionResolveProbes` (0x80073450), using eight grid probes and separate dispatch tables at 0x800B20E0 / 0x800B2108. Nine dispatch roots were missing function definitions in the private copy and were defined there from their proven table entries and negative-stack prologues.

`GetZoneMaskXZ` returns coordinate-sign quadrant bits (1, 0x10, 0x100, 0x1000), not the visibility-zone-box mask. `ColliderComputeZoneMask` ORs the four corners. These distinctions need to remain separate in the port.

## Current limits / next steps

The viewer uses original static response and complete floor queries. Development controls remain separate from PlayerUpdate: 30 Hz ticks, speed6 exported units/second, radius128/height512 proxy, floor snapping and rejection of floor changes over128 PSX units. Walking validation includes terrainless area0x0E and a real box-contact fixture. Unsupported response classes reject walking explicitly; asset inspection can still load them.

Original player controls, landing, jump/gravity, damage, rope/climbing state, dynamic collider motion and moving platforms remain separate work. The tests reproduce physical response with the player-body global cleared; they do not establish equivalence for callbacks that change player state. Next work should reconstruct player landing/movement states and integrate collider updates.
