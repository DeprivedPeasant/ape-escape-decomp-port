# Native sound player (`tools/native_audio/`)

Portable C99 code for the native port's audio: `sp_player.c` / `sp_player.h` (no dependencies besides libc / libm,
no game data inside; the caller passes the bank members and the `SCUS_944.23` image, from which the pan / volume law
tables 0x800B3D90 / 0x800B4190 and the pitch table 0x800B38D0, the reverb presets 0x800B41D0 and the effect table 0x800B2D08 are read).

## Music: `SpPlayer`

```c
SpPlayer *p = sp_create(bank, bank_size, exe, exe_size, -1 /* loop forever */, 0, 4, 10);  // preset 4, volume 10 as the game
sp_render(p, out, frames);  // 44.1 kHz stereo float, interleaved
sp_destroy(p);
```

A streaming version of the model of `tools/render_seq.py` (notes/23, notes/24): SSsq events executed at their
sample time (tempo changes, loop markers with a loop count: 1 = straight through, -1 = forever as in the game), the
program of a note taken after all events of its tick, sustain pedal, program / layer selection (layered, key split,
key indexed kits), the game's integer volume, pan and pitch laws, streaming SPU ADPCM with repeat history and Gaussian interpolation,
the envelope model of `render_seq.envelope` evaluated per sample, the modulation LFO, the 24 voice allocator
(`SeqAllocVoice`, voice stealing) and the SPU reverb (per sample, with buffer saturation).

## Sound effects: `SpSfx`

```c
SpSfx *s = sp_sfx_create(exe, exe_size);
sp_sfx_bank(s, 0, member_00B, size, member_00A, size);       // common effects
sp_sfx_bank(s, 2, stage_shd1, size, stage_vb1, size);         // the stage's effect bank (second SShd / VB pair)
int h = sp_sfx_play_id(s, 12);                                 // PlaySfx(12)
sp_sfx_stop(s, h);                                             // key off (looping effects)
sp_sfx_render(s, out, frames);
```

The model of `tools/render_sfx.py` (notes/24, notes/29): effect sequences at 480 ticks per second, key on / key off,
volume and pan ramps and pitch glides of the extended controllers.

## Validation (`tools/native_audio/check_player.py`)

The script builds the DLL with gcc (`-Wall -Wextra -Werror`) and compares through ctypes:

* original validation before the correction below: songs: `check_player.py --all` renders every bank with `render_seq.py --npy` (unnormalised reference) and with the C
  player; all 43 songs agree: relative RMS difference 2.5e-8 for most, at most 2.4e-5 (0AD, which steals 1,642
  voices on both sides), peak differences below 1e-3 of the peak. (A first run found one ordering bug: a key off and new
  notes on the same tick must make the released voice stealable first, as `render_seq` knows key offs in advance.)
* effects: `check_player.py --sfx [--bank 01B]` renders every PlaySfx id with `render_sfx.render` and the C mixer;
  all 172 common effects and the stage effects of 01B / 08F / 0E5 / 10A agree to a relative peak difference of
  4e-7.

Differences come from float32 output, per sample (C) versus vectorised (numpy) evaluation of the same formulas and the
reverb saturation (applied per sample in C, only at the block level in numpy).

`sp_render_wav.c` is a small command line front end (`gcc -std=c11 -O2 sp_player.c sp_render_wav.c -o sp_render_wav -lm`;
`sp_render_wav bank.bin SCUS_944.23 out.wav [loops] [max seconds]`); it renders about 30x faster than real time.

Not modelled in the first version (as in the Python tools): frame quantised event timing (the driver runs at 60 Hz) and
the effects sharing the 24 voices with the music (`SeqVoiceAlloc`); both were added later (sections below: frame clock,
shared voice pool, integer ADSR and reverb). Still open: portamento in songs, controllers 2 / 0x60 in effects.

## Sustained music fidelity correction (Codex, 2026-10-06)

Generated by `python tools/codex/write_music_report.py` from the completed checks.
This section supersedes the earlier cubic/pitch approximations in notes/23 and notes/24.

The user-reported `extract/native_audio/136_ref.wav` was current: the pre-fix C render and
saved Python array agreed to relative RMS 3.73e-8, and normalized WAVs differed by at most
one PCM LSB. The issue was shared playback behavior rather than a stale export.

`SeqPitchFromNote` (0x8009E594) indexes halfwords at 0x800B38D0, adding a signed fine-tune
value and `(bendRange * (bend - 64)) >> 2`, then applies integer octave shifts and a
16-bit result mask. The SPU clamps pitch to 0x4000. Music now uses those actual EXE data,
integer LFO scaling, and increments by an exact multiple of 1/4096 input samples.
Program 28's paired Time Station pads use pitches 1490,1479,1495,1485, confirmed both
by original instructions and an independently executed PSF register trace. Floating
exponentiation previously produced 1490.589,1479.865,1495.980,1485.217; the altered
relative detuning changes beating and produces phase drift in held notes. The first
pair starts at 0.0035/0.0456 seconds, with approximately 10.783-second key-on durations.

Music voices now carry ADPCM predictor and interpolation history through each repeat
jump, with fixed-size decoder state. The four-tap filter uses the physical SPU ROM
coefficients, eight fraction bits, and integer products. The all-ones sustain rate
holds its level. Legacy SFX helpers retain their previously validated behavior.
Hardware facts and ROM data: [PSX-SPX SPU reference](https://psx-spx.consoledev.net/ps1/spu/soundprocessingunitspu/).
No emulator implementation or game data was copied into the player.

Independent references: the [Zophar PSF set](https://www.zophar.net/music/playstation-psf/ape-escape)
contains byte-identical local member-136 SSsq, SShd0 and VB0. Its replacement Wild Arms 2
driver is useful for SPU registers, but does not prove Ape Escape event/loop timing.
`render_psf_reference.py` runs a pinned [Audacious PSF core](https://github.com/audacious-media-player/audacious-plugins/tree/master/src/psf)
using HLE; `check_spu_reference.py` runs a pinned Highly Experimental SPU core with
isolated tones. These are separate test executables/libraries under ignored extract/;
they require no BIOS image and are never linked into the native port.

Validation:

- 9,942 randomized valid pitch cases match original MIPS instructions and both C/Python.
  58 artificial out-of-table combinations are explicitly excluded; real songs are checked separately.
- 558,376 C/Python sample positions agree exactly across four held-note samples,
  multiple repeat boundaries, variable rates and all 256 interpolation fractions.
- Four independent 11-second sustained-oscillator checks all improve. The metric below
  permits a constant gain and at most eight startup samples of alignment; it never
  stretches time or re-aligns individual windows. ADSR shape, event timing and reverb
  are excluded. Residual core differences mean this is not a bit-exact SPU claim.

## Whistle modulation follow-up (Codex, 2026-10-06)

The user's remaining warble near43s/64s is channel6/program3/sample0x1DD80,
not the program28 pad tested earlier. Its long notes begin43.132/44.143 and
64.705/65.716seconds. Controller1 changes the modulation depth between10 and50;
the sequence also contains explicit pitch-bend slides.

Original SeqUpdateVoices (0x8009CE18), with normal-music mode +0x1C=0, first
decomposes the written channel bend into signed note and fine offsets, using
truncation toward zero. It then applies the modulation waveform with a
ONE-semitone range. The previous model replaced channel bend with the waveform
and used the tone's12-semitone bend range, losing the slides and making the
vibrato twelve times too wide. The corrected music helper reproduces the
normalization, signed8-bit fine wrapping, and separate small modulation lookup.
Flag0x40 also correctly selects program header[5] as the curve index.

`python tools/codex/check_whistle_modulation.py` validates C and Python against
1500 executions of the original full SeqUpdateVoices routine (24-slot
loop, one seeded music voice, seven real curves). All cases pass. The whistle
line has 181 distinct real bend/depth combinations in the reported windows;
maximum modulation pitch span drops from 2052 to 207 SPU pitch units.
The current all-song sweep revalidates43 complete songs after this correction.

A separate80-second PSF trace supports the whistle's written pitch slides, but
its replacement driver does not reproduce Ape Escape's modulation. The original
instruction routine is the authority for this fix. Earlier pad-only comparisons
were not sufficient to establish correctness of this other instrument.

Current full output: extract/native_audio/136_ref.wav and136.wav; a distinct listening
copy is extract/codex/audio-audit/time_station_whistle_corrected_full.wav. Focused
comparison: extract/codex/audio-audit/time_station_whistle_fixed_40-76s.wav,
with prior output at time_station_whistle_before_40-76s.wav.
Original frame quantization and additional modulation controller/state edge
cases remain separate fidelity work; this correction does not claim bit-exact
whole-song playback or listening QA.


## Original frame sequencer clock (Codex local follow-up)

`SP_FRAME_TIMING` selects the original60Hz delta clock for music. `sp_sfx_frame_timing(s,1)` applies it to effects; native SDL viewer enables both. Standalone renderers retain sample timing by default for existing waveform/reference comparisons, so previously approved TimeStation exports remain unchanged.

`sp_delta_frames` implements SeqReadDelta800A01BC: rate=floor(tempo*PPQ*10/(60*60)), scaled delta*10 plus signed carry, prior round-up subtracts one rate, signed remainder retained; nearest-frame rounding uses the original strict comparison(rate<2*remainder). Tempo changes retain carry. SeqTick drains zero-delta events and decrements a positive frame delta once each tick; native event scheduling advances735samples per frame. SFX uses original fixed60BPM/480PPQ and aligns new requests to the next global735sample boundary.

Validation: `python tools/codex/check_seq_clock.py`:9696original-instruction frame/remainder/roundUp comparisons, including8196realTimeStationevents,0failures. Quantized music chunk independence735/1024sample blocks over132300frames is bit-identical. Original whistle1500cases and174legacyeffect reference comparisons still pass. Clock tests do not establish all sequencer/controller semantics.

SDL native adapter now sums music and common/stage effects, with page/close effect0 and a stage-effect audition. This is still separate music/SFX voice allocation; shared24voice arbitration, exactADSRcounter stepping and integerreverb remain pending. See notes/port/native_presentation.md for integration scope. No new whole-song listening comparison claimed.


## Shared music/effect voice pool (Codex local follow-up)

The earlier separate-allocator limitation is now addressed in the native viewer. `SpMix` connects newly created music/effect inputs to one24slot pool; effects use the original8voice limit, matching-ID reuse, priority stealing and allocation-age rules. `sp_voice_pool.h` implements the two original selection policies. `check_voice_pool.py` compares return/cursor/count/effect-count and all24age writes with6000original SeqAllocVoice8009DAB4 / SeqVoiceAlloc8009DCA0 executions,0failures.

Mixed rendering drains music before due effect voices, then mixes each sample after shared allocations so a stolen music voice is silenced. SDL uses this shared mixer; standalone music/SFX reference APIs stay available. Stream stress:45secondsTimeStationwarmup followed by64common-effect requests, peak24voices/effects<=8,7dropped;176400postburstframes match bit-for-bit across735/512sample callback sizes. Original-selection validation does not establish exact envelope-dependent free timing or original SFX track ordering. Lifetime still follows existing approximate envelope/one-shot logic; shared music+effect integer reverb remains pending (effects currently dry). ExactADSRcounters and integerreverb remain the next fidelity targets.
