# Overlay member 180: title and sequence player

The member loads at `0x80136000`. Its main entry is `Mode_Title`; `SeqPlayer_Run` loads and plays one sequence, then the title entry selects the next game mode. The C ports are in `src/modes/ae_ovl180.c` and `ae_ovl180.h`. `tools/mips/check_ovl180.py` loads the real EXE, member 180, and area members for areas 1, 2, and 3.

## Renderer and platform hooks

The stream/display path keeps its mode state in C and calls hardware-facing work through named hooks:

- `SeqPlayer_CdReadSeek`, `SeqPlayer_CdPlayXaRange`, `SeqPlayer_LoadFiles`, `SeqPlayer_StGetNextWait`, `SeqPlayer_CdSetFilter`, `SeqPlayer_CdReadAsync`, `SeqPlayer_GetBusy`, and `SeqPlayer_CdReadyCallback` own CD/XA commands, asynchronous sector reads, and stream-ring waits.
- `SeqPlayer_CopyScreenToBack`, `SeqPlayer_SetupDisplay`, `SeqPlayer_Present`, `SeqPlayer_LoadSavedImage`, and `SeqPlayer_SaveRestoreVram` own framebuffer, display-environment, and VRAM operations.
- `SeqPlayer_DrawSprite`, `SeqPlayer_DrawText`, `SeqPlayer_DrawLitMesh`, `SeqPlayer_PoseToMatrix`, `SeqPlayer_PoseModel`, and `SeqPlayer_PoseModelMatrices` do rendering, skinning, text, GTE setup, or GPU packet work.
- Other PsyQ/BIOS hooks carry their original arguments: `VSyncCallback`, `ReadGeomScreen`, `MeshInit`, `LoadListStart/Step`, `StSetRing/Stream`, `StFree`, `StRingStatus`, `CdSync`, `CdPosToInt`, `CdIntToPos`, `CdReady`, `XaPlay`, `SoundStopAndRestoreVolume`, `SetDispMask`, `DrawSync`, `PutDispEnv`, `PutDrawEnv`, `DrawOTag`, `SetGeomScreen`, `srand`, and `memcpy`.
- The direct verified subsystem ports use native callbacks for `SetRotMatrix`, `SetTransMatrix`, `Gadget4TrailUpdate`, `GadgetFlashUpdate`, `PadGetState`, `PadInfoMode`, `PadSetupDualShock`, `PadDemoPlaybackStep`, `StageRequest`, `StickToButtons`, and `PadRumbleReset`.

Command-table targets that only prepare display state or draw pose/model/primitive, sprite, particle, trail, text, message, color, or model packets remain renderer hooks. The checker and C module use descriptive hook labels for the targets without names in the symbol inventory. Empty command stubs at `80137DAC`, `80138344`, `8013834C`, `801383FC`, `80138728`, `801388D8`, `801388E0`, `801388E8`, and `80138CDC` do no work.

Three command targets change sequence state and are C ports: `80139FA0` selects the sweep mode and clears its timer; `80139FB8` advances the 16-bit timer with the original signed threshold and passes the resulting mode/timer to the renderer; `80139EC4` applies indexed object-flag bytes. `SeqPlayer_DisplayStateInit` (`80136604`) was called `SeqPlayer_Nop` by the inventory, but its instructions call `VSyncCallback` and `ReadGeomScreen` and copy display timing globals. It is named from that behavior here.

`SeqPlayer_Run` calls the already verified `EffectScriptUpdate`, `EffectsUpdateAll`, and `PadUpdate` ports directly. Small non-original adapters in the checker bind those ports to this overlay's native matrix, effect, pad, and stage-request hooks.

## Findings

- `SeqPlayer_Run` uses the sequence file word at `+20` as the frame limit. A zero-sized record's halfword at `+2` distinguishes a natural end from a frame record.
- Stop reasons differ: initial stream failure calls `Stop(2)`, input and later stream failures call `Stop(1)`, and the frame limit/natural end call `Stop(0)`; the return is 1 for the first three cases and 0 for natural end.
- The transition-sweep timer wraps when its signed 16-bit value reaches 193; on wrap, the timer becomes the sweep mode byte.
- The parser's model references are inline data offsets. Composite records copy their auxiliary data into the sequence-player staging area before object initialization.

No existing function-inventory rows were changed. `tools/check_verified.py` was left unchanged; its source scan already discovers the new `src/modes/ae_ovl180.c` file.
