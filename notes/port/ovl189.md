# Leave Hub overlay 189 port

This port covers every function in `extract/members/189.bin`, loaded at `0x80136000`. Gameplay state, route selection,
progress checks, fades, input, transition timing, and camera math use structured C in `src/modes/ae_ovl189.c`. Calls to
verified game ports are direct; CD/archive, GPU, display, sound, and remaining external game services stay named hooks
in `AeOvl189Hooks` or the existing subsystem hook tables.

SaveUi_LookAt_189

`HubExitUi_IsDestinationUnlocked`, `HubExitUi_GetProgress`, and `HubExitUi_GetFlags` read the packed route and progress
tables. `SaveUi_StringTableIndex_189` handles the packed, NUL-terminated strings; `HubExitUi_TextWidth` counts the
original text widths. `HubExitUi_DrawModelA/B/C` are ported through matrix construction and the values sent to mesh
rendering. A/B execute their original matrix and mesh-transform instructions while the inline GTE projection loop is
replaced by `HubExitUi_ProjectModelVertices`; C executes fully and calls the existing `MeshCalcEnvUVs` port. Primitive
submission, rigid-model transformation, environment-map drawing, and vertex projection remain named renderer hooks.
`HubExitUi_DrawText` is ported because it advances the shared object-random seed and text X coordinate while emitting
each glyph through a renderer hook.

The A/B projection-loop and text packet-store coverage exclusions are registered in `tools/mips/check_exclusions.csv`.
The model store audit lists every stack, GTE-context, and projection-output store below. Their matrix and mesh-transform
values are compared, and the only skipped model instructions are the inline projection loops that write renderer-owned
scratch output. The text checker runs the original function for every case. It intercepts only the listed packet field
and ordering-table link stores; the seed and text-position updates remain visible to differential RAM comparison. The
shared ordering-table cursor remains covered by the existing renderer-owned cursor mask.

The 489 Mode exclusions consist of 473 instructions replaced by named renderer hooks and 16 instructions in three
unreachable branches. The renderer bodies are declared in `tools/mips/check_exclusions.csv`; they are not treated as
game-logic coverage. The three branch proofs are:

* `80136388..8013638C`: negative-angle rounding. The angle starts at zero and adds a positive step no greater than 240
  each frame. With the oracle's 2,000,000-instruction call budget, even the loose bound of one frame per instruction
  keeps the angle below 480,000,000, so it cannot become negative.
* `80136E0C..80136E10`: fallback for negative transition states other than -1 and -2 after a negative route result.
  `HubExitUi_Run` returns before route handling whenever transition state is nonzero, so a negative route result reaches
  this block only with transition state equal to zero.
* `801374DC..801374F0` and `801374F4..80137508`: jump-table entries for `HubExitUi_Run` results -2 and -1. Mode holds
  screen state at 3, where `Run` returns 0 or `screen_route_update` results -7, -3, -6, -8, and -4.

## Port findings

* `Mode_LeaveHub` does not clear the incoming transition-state global during setup. It preserves the value and later
  advances only the transition states `-1`, `-2`, `1`, and `2` back to zero. The long camera scenario caught an
  accidental C reset because it changed camera-distance state, stage-render arguments, and the final hook sequence.
* The route menu and its data tables retain separate destination selection, route selection, and route slot fields.
  Previous/next destination transitions and locked-route fallback are covered independently in `HubExitUi_Run`.
* `HubExitUi_DrawText` advances the shared seed at `800AE8F2` by `seed = seed * 5 + 1` once per glyph and advances
  the halfword text X coordinate at `80139CF0` by the character-width table entry. Those stores were hidden by the
  former full-function drawing hook; the checker now executes the original function and compares both updates.
* `HubExitUi_DrawModelA/B/C` store stack locals, GTE context fields, and projected-vertex scratch. The store audit
  identifies each original store in the drawing functions. A/B matrix construction and `MeshTransform` execute and
  compare; their 21-instruction RTPT projection loops are the registered renderer boundary. C has full instruction
  coverage, including the call into the existing `MeshCalcEnvUVs` port.
* The model routines read position components as signed halfwords at offsets 0, 2, and 4. The C matrix helper keeps
  those packed offsets separate from the 32-bit vectors used by the camera code. The decoration loop also carries the
  current angle into the first model's Y rotation, then clears that component before applying the next Z rotation.
* `VramScrollUpdate` receives the original live stack pointer in the checker bridge so its temporary rectangle matches
  the caller's frame and does not overwrite Mode locals.
* Loading and display loops preserve the original call order; the checker bounds each MIPS call to 2,000,000
  instructions. The direct `HubExitUi_Run` cases cover its load, menu, route, transition, cancel, and accept paths.
