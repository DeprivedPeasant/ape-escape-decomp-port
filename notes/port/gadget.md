# Gadget RAM-image port

This batch ports the 25 `Gadget*` entries listed in `extract/codex-task/task.md` to structured C over `AeRam`.
The inventory below was built from the original `jal` instructions in SCUS-944.23 before implementation. A call to
another function in this batch is a direct C call. A call to an already verified RAM-image function is also direct;
unverified game and SDK functions outside this batch stay named entries in `AeGadgetHooks`.

All 25 entries are implemented in `src/player/ae_gadget.c`. Calls within this batch and calls to verified math, world,
and collision ports are direct. Other game and SDK calls remain named hooks. Four native renderer hooks replace inline
GTE/GPU packet blocks while leaving the surrounding trail, aim, and update logic in C. In particular,
`Gadget4TrailReset` owns the 40 records at `0x800F4ED0` and masks the low five bits of each record's `+6` halfword.

## Evidence and validation

The source evidence is the function listings generated by `tools/mips/mips_ram.py` from the game EXE and the names /
comments in `tools/symbols.csv`. Struct layouts and player field names come from `tools/structs.txt`, `notes/08-player.md`,
and `notes/70-native-player.md`. The differential checker is `tools/mips/check_gadget.py`; it loads SCUS-944.23 and a
real area member into both sides, compares return values where defined, all RAM outside the registered top-of-stack
window, scratchpad, and named hook effects. Per-function case counts, instruction coverage and mutation results are
recorded here after the checker is complete.

The four renderer ranges are `Gadget7TrailUpdate 8006D27C..8006D488`, `Gadget4TrailUpdate 8006DE00..8006DFE0`,
`Gadget3UpdateDraw 8009AE9C..8009B054`, and `Gadget3UpdateDraw 8009B094..8009B1A4`. They are replaced by the named
`GpuDrawGadget7Trail`, `GpuDrawGadget4Trail`, `GpuProjectGadget3Aim`, and `GpuDrawGadget3AimLine` hooks respectively.
The first two cover inline projection/culling and GPU trail packets; the Slingback hooks cover screen projection and
line-primitive packet construction. Their exclusion rows are in `tools/mips/check_exclusions.csv`.

The remaining eight-instruction exclusion in `Gadget4PlayerUpdate` (`8007A774..8007A790`) is the second rumble block.
The first rumble check tests and clears the left-body pointer on a contact hit. The second check is gated by the
right-body pointer but reloads the left-body pointer and tests the same contact nibble, so it cannot reach the block:
the first hit clears that pointer, and without a first hit the repeated contact test is false.

The default run executes 2,554 of 2,995 original instructions; the remaining 441 are exactly the five registered
coverage exclusions above. No declared range executed. The checker also passes the full `--trapv` run with 485 cases.
Its `--mutate` mode builds 50 wrong copies (two per each of the 25 functions), each with an unexpected RAM store, and
the differential checker catches all 50. Mutation insertion is anchored to each C definition. `tools/check_verified.py`
reports zero errors; its warnings are missing result files for unrelated checkers.

Other hooks in `AeGadgetHooks` belong to the previously ported functions or are nested under the verified world and
collision calls. `CollisionBodyAlloc`, `CollisionBodyRegister`, the SDK matrix/trig functions, ground/surface queries,
and calls between gadget ports remain direct where their verified `AeRam` interfaces match.

The direct subcalls also retain their named dependencies: `Gadget4BuildMatrix` uses `MatrixRotYMul`,
`SdkVectorHelper_800305B0`, and the model hooks; `Gadget3FindAimTarget` uses `CameraGetSlotTarget`,
`TargetListFindBest`, `SdkVectorHelper_80031330`, `AimReticleDrawCircle`, and `PlaySfx`. Calls forwarded by the verified
world and collision ports remain hooks too: `GetSolidHeight`, `PlaySfxAt`, `GimmickActivate`, `MeshInitFromAreaTable`,
`AreaEffect`, `CameraShake`, `EventCamStart`, `PrintfError`, `SoundLoopStart`, `SoundLoopStop`, `GimmickTypeToSfx`,
`PickupCollect`, and `CameraNudge`.

Instruction review found these material details already reflected in the validated code: the sparkle gate used by
`Gadget6SparkleFx` resolves to 0x800EC350; `Gadget4BuildMatrix` mode values outside 0 and 1 consume caller `$s1`;
Super Hoop speed/ring math preserves MIPS-width arithmetic; and the second `Gadget4PlayerUpdate` rumble branch is
unreachable due to its repeated left-body test. The checker supplies the same explicit `$s1` value to MIPS and C, and
all coverage exclusions are registered in `tools/mips/check_exclusions.csv`.
The five new `unreachable` rows are concrete review items for the project owner, as required by
`notes/port/validation/ledger.md`.
