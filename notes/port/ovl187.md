# Stage clear overlay member 187

This batch ports all 23 functions in `extract/members/187.bin` to
`src/modes/ae_ovl187.c` and declares the public functions and hook table in
`src/modes/ae_ovl187.h`. Every function has a `diffed` row in `tools/verified.csv`;
its notes field is `overlay member 187.bin`.

## Call tree and behavior

`Mode_StageClear` configures the display, loads the stage-clear assets, calls
`StageClearUi_Setup`, and drives the wipe and frame loop. The loop advances
the script, updates camera and animated object state, draws the backdrop,
scanlines or ripple grid, stars and time labels, then handles input and mode
exit. `StageClearUi_DrawWipe` initializes model instances from the active
area member and advances its load, opening, display, and closing states.
`StageClearUi_RunScript` dispatches the embedded UI commands to the text,
object, sound, and strip-copy routines. `StageClearUi_UpdateObjects` advances
scripted transforms before calling the model path. `StageClearUi_DrawStars`
calls `StageClearUi_ObjMatrix` for each of its five marks. `RippleGrid_Init`,
`RippleGrid_Smooth`, and `RippleGrid_Draw` initialize, update, and submit the
water ripple grid.

Several details were taken from the instruction stream where a simplified
reading would differ:

- In `StageClearUi_DrawStars`, areas 19 and 36 call the stage-result query and
  require both result bits. The other-area branch jumps directly to the draw
  loop and renders the five marks without that query.
- The setup rank is an ordered threshold class from 0 through 3, where 3 is
  the fastest class. A better class than the saved time selects the matching
  rank text and rank value. Cases also cover tied and lower times, suppressed
  rank text, and the non-stage modes.
- `StageClearUi_DrawText` reads the spacing field as a signed 32-bit word;
  negative spacing is multiplied at that width. `DrawScanlines` uses a signed
  32-bit timer and selects the low brightness limit before advancing an
  expired timer.
- `Mode_StageClear` preserves different delay-slot byte values when it routes
  the two special areas at exit. The incomplete-result marker belongs at
  `GAME_STATE + 0x2CE`, not in the UI object.

Direct calls reuse already verified ports where present, including
`AreaGetLevel`, `AreaSetZoneBoxes`, `ProgressGetByte`, `ModelInit`,
`MatrixRotYMul`, the SDK matrix/vector math, `PlaySfx`, `SoundStop`, `XaPlay`,
and `PadUpdate`.

## Exclusions and remaining limits

The checker excludes the MIPS stack window `801FF000..80200000`, the UI order
cursor at `800EC354:4`, the test ordering table at `801D0000:65536`, per-object
ordering-table link spans at `800F03CC+0x4078x32+0x00:8` and
`800F03CC+0x4078x32+0x02:4/8`, and the tail link at `800F43CC:8`. These bytes
are host-stack or renderer-owned packet/link state; the surrounding game RAM,
scratchpad, and non-render hook sequences are still compared.

The renderer request tuples are captured but cannot be compared to a matching
MIPS call: the original overlay emits inline GPU/GTE packets instead. Their
request-argument blind spot and the low-level renderer-only events are
declared in the exclusion registry. `RenderStageClear*` and ripple packet
contents, OT link addresses, and the returned order-table cursor therefore
remain the renderer integration's responsibility.

The remaining uncovered instruction ranges have these proofs:

- `StageClearUi_DrawWipe`: the 192-pixel clamp branches are skipped because
  signed timer values below 6 produce a width at most 192.
- `StageClearUi_RunScript`: command opcodes are aligned by the `0x3FC0` mask;
  interpolation divisions occur only with positive remaining-frame counts.
- `StageClearUi_DrawBlinkIcons`: its signed loop index starts at zero and
  remains nonnegative.
- `StageClearUi_UpdateObjects`: interpolation divides only after each signed
  halfword frame count was found positive, so zero and minus-one divisors are
  impossible.
- `StageClearUi_DrawScanlines`: timer duration is positive and at least four;
  its denominator traps and negative-width packet arm cannot be reached.
- `StageClearUi_Setup`: the rank classifier yields only 0..3, so the switch
  fallback arms are impossible after the better-rank condition.
